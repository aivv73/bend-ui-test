# API UITest

Модуль импортируется как `import ./uitest.bend as UITest`.
`WindowRef` и `Event` определены в Base вашего форка Bend.

| Вызов | Результат | Поведение |
|---|---|---|
| `UITest.key(ref, code)` | `IO(Result<&1, &1, U32 & String, Unit>)` | Клавиша нажата и отпущена. `code` имеет тип `U32` и совпадает с кодом `Event.Key`. |
| `UITest.click(ref, x, y)` | `IO(Result<&1, &1, U32 & String, Unit>)` | Левая кнопка нажата и отпущена в пикселях клиентской области. `x` и `y` имеют тип `U32`. |
| `UITest.request_close(ref)` | `IO(Result<&1, &1, U32 & String, Unit>)` | Приложению отправлен `WM_DELETE_WINDOW`, который Bend получает как `Close{}`. |
| `UITest.alive(ref)` | `IO(Result<&1, &1, U32 & String, Bool>)` | `Done{True{}}` для существующего окна, `Done{False{}}` для исчезнувшего окна. |

`Done{Unit{}}` означает, что X11-сервер принял отправку.
Это не подтверждение обработки события приложением.
Для упорядоченных действий над одним окном используются последовательные вызовы в `do IO`.
Между независимыми вычислениями общего порядка нет.

## Коды клавиш

| Клавиша | Код Bend |
|---|---|
| `a`, `!`, пробел | `97`, `33`, `32` |
| Tab, Enter, Escape, Backspace | `9`, `13`, `27`, `127` |
| Up, Down, Left, Right | `63232`, `63233`, `63234`, `63235` |
| F1 ... F12 | `63236` ... `63247` |
| Insert, Delete, Home, End | `63271`, `63272`, `63273`, `63275` |
| Page Up, Page Down | `63276`, `63277` |
| Shift слева, Shift справа | `65592`, `65596` |
| Control слева, Control справа | `65595`, `65598` |

Код не является X11 KeySym или физическим keycode.
Бэкенд подбирает keycode и Shift или Lock для текущей раскладки, чтобы декодер Bend вернул заданный код.
Для резервных кодов `65536 + keycode` также требуется точное совпадение результата декодера.

Bend приводит латинские заглавные буквы к строчным. Например, `65` отклоняется, а `97` соответствует `a`.
Это API событий клавиатуры. Оно не вводит произвольный Unicode-текст и не сохраняет состояние модификатора между вызовами.

## Координаты и владение

Начало координат находится в левом верхнем углу содержимого окна.
Рамка окна и положение на рабочем столе не учитываются.
Допустимы `x < width`, `y < height`, `x <= 32767`, `y <= 32767`.
В Bend левая кнопка имеет номер `0`.

Библиотека открывает временное соединение с дисплеем, указанным в ссылке.
Она не перемещает курсор и не меняет фокус или глобальное состояние клавиш.
`Window` остаётся у приложения. `request_close` не уничтожает окно.
Ссылка истекает вместе с владельцем окна.

## Ошибки

Ошибки представлены как `Fail{(errno, message)}`.

| Код Linux | Причина |
|---|---|
| `2`, ENOENT | Дисплей недоступен или окно исчезло перед отправкой. Для исчезнувшего окна `alive` возвращает `Done{False{}}`. |
| `22`, EINVAL | Пустое имя дисплея, встроенный NUL, нулевой ID, неверный код клавиши или координаты. |
| `95`, ENOTSUP | Клавиша недоступна в раскладке, окно не принимает нужные события, отсутствует `WM_DELETE_WINDOW` или бэкенд не поддерживается. |
| `11`, EAGAIN | X11 сообщил `BadMatch`. |
| `5`, EIO | Другая ошибка протокола X11 или отправки. |

JavaScript всегда возвращает `Fail` с кодом `95` для всех четырёх операций.
Native-бэкенд вне Linux возвращает платформенный ENOTSUP.

## Ограничения

Поддерживаются native-окна Bend под X11 и Xwayland. Чистый Wayland и JavaScript не поддерживают отправку.
Декодер клавиш соответствует форку на коммите `de38700481244494b56a2f947df6fba25f798887`.
Смена раскладки после создания окна может рассинхронизировать кеш декодера владельца и новое соединение отправителя.

`alive` показывает существование окна в момент запроса.
X11 может переиспользовать ID, а `WindowRef` не содержит поколения ресурса.
Проверка `alive` не гарантирует успешность следующего вызова.

Если окно исчезло между двумя событиями, нажатие может уже дойти, а вызов вернёт `Fail`.
При разрыве соединения с самим X11-сервером Xlib может завершить процесс.
Обработка устаревших ID не обеспечивает восстановление после такого разрыва или таймаут XSync.
